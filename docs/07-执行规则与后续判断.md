# 执行规则与四周后判断

## WebSocket 什么时候再加

只有满足下面条件才考虑：

```text
第 1～3 周全部已完成
网页轮询已经稳定
还有余力
```

这时再看：

FastAPI WebSocket 官方教程：

https://fastapi.tiangolo.com/advanced/websockets/

否则：

```text
2 秒轮询完全合格
```

## 视频使用规则

https://www.bilibili.com/video/BV1HADnYFEXn/

```text

```

https://www.bilibili.com/video/BV1zV2QBtE39/

```text
GET / POST

```

## 卡住时怎么处理

如果某个环境问题卡超过 1 小时，例如：

```text
pip 装不上
MQTT 连不上
FastAPI 起不来
Topic 收不到
```

当天目标改成记录：

1. 现象
2. 报错
3. 已试过什么
4. 最后卡在哪

不要通过继续刷视频来“假装推进”。

## 4 周后的判断

只问自己四个问题。

### 1. 你是否主动愿意继续改？

不是因为计划要求，而是自己想继续加东西。

### 2. 看到设备状态真的改变时，有没有比 CRUD 更有反馈？

例如：

```text
浏览器 STOP
↓
模拟设备真的停止
```

### 3. 出 Bug 时，你想排查还是只想关 IDE？

例如 MQTT 不通：

```text
你会想查 Topic / Broker / 回调吗？
```

还是：

```text
只觉得烦？
```

### 4. 最终有没有一个 3 分钟 Demo？

如果有，而且你明显喜欢：

后续再考虑：

```text
工业 IoT 后端
设备平台
设备集成
ESP32
ROS2
```

如果还是觉得：

> “就是换一种方式写接口。”

那下一步更应该看：

```text
实施
现场集成
自动化
PLC
技术支持
```

而不是继续盲目叠：

```text
LangGraph
MCP
ROS2
下一门语言
```

## 每天建议投入

工作日：

```text
视频 / 文档    20~30 min
实际写代码      60~90 min
记录 / Git      10~15 min
```

周末：

```text
2~4 小时
```

比例：

```text
20% 学
80% 做
```

核心原则：

> **项目能继续推进，就不要继续刷课。**
