# 验收范围与技术约定

## 4 周后的最低验收标准

只要下面 6 件事做出来，这个实验就算成功：

1. Python 模拟设备通过 MQTT 持续上报温度、RPM、状态。
2. FastAPI 读到的是 MQTT 真数据，而不是写死的假数据。
3. `POST /command STOP` 能经 MQTT 让模拟器从 `RUNNING` 变成 `STOPPED`。
4. 关闭模拟器后，后端能根据 `last_seen` 判断设备 `OFFLINE`。
5. 强制高温后，只产生 **1 条未解除报警**，不会每秒重复插入。
6. 一个简单网页能显示设备状态，并且有一个真的有效的 `STOP` 按钮。

## Broker 和 Topic 统一配置

全程默认使用：

```text
broker.emqx.io
port: 1883
```

除非确认公共 Broker 本身异常，否则不要中途更换。

第一天就建立统一配置：

```python
BROKER = "broker.emqx.io"
PORT = 1883

PREFIX = "zcufe-demo-自己设置一个随机串"
DEVICE_ID = "001"
```

Topic：

```text
{PREFIX}/device/001/telemetry
{PREFIX}/device/001/status
{PREFIX}/device/001/command
```

例如：

```text
zcufe-demo-a7f31/device/001/telemetry
zcufe-demo-a7f31/device/001/status
zcufe-demo-a7f31/device/001/command
```

Publisher、虚拟设备、FastAPI、MQTTX 必须全部使用同一套前缀。

## 推进方式：以里程碑为主，不死卡“第几天”

核心里程碑：

```text
M1 MQTT 单向通信
M2 MQTT 双向控制
M3 FastAPI 接入
M4 在线 / 离线
M5 SQLite 历史数据
M6 高温报警
M7 网页控制闭环
```

一天做两个里程碑可以。

一个里程碑做两天也可以。

不要为了追进度条而强行加功能。
